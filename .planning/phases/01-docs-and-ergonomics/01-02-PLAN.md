  <name>JsonParser API Expansion — string input, single-dict input, parse() one-liner</name>
  <files>src/json_parser/__init__.py, tests/test_json_parser.py</files>
  <behavior>
Three new behaviors, each tested independently:

**API-01: Raw JSON string input**
- `JsonParser('{"name": "Alice"}', ["name"])` — should work (parser calls json.loads internally)
- `JsonParser('[{"name": "Alice"}]', ["name"])` — JSON array string also works
- `JsonParser("not valid json", ["name"])` — raises JsonParserException with descriptive message (NOT bare json.JSONDecodeError)

Test cases:
- `JsonParser(json.dumps([{"name": "Alice"}]), ["name"]).get_data()` → `[{"name": "Alice"}]`
- `JsonParser(json.dumps({"name": "Bob"}), ["name"]).get_data()` → `[{"name": "Bob"}]`
- `JsonParser("bad json", ["name"])` → raises `JsonParserException`

**API-02: Single dict input**
- `JsonParser({"name": "Alice", "age": 30}, ["name"])` — single dict, not in a list
- Result is a one-element list, same shape as list-of-dicts result

Test cases:
- `JsonParser({"name": "Alice", "age": 30}, ["name"]).get_data()` → `[{"name": "Alice"}]`
- `JsonParser({"nested": {"city": "Portland"}}, ["city"]).get_data()` → `[{"city": "Portland"}]`

**API-03: Module-level parse() function**
- `from json_parser import parse` — importable at module level
- `parse(data, keys)` — equivalent to `JsonParser(data, keys).get_data()`
- Accepts all the same input types as JsonParser (list-of-dicts, single dict, JSON string)

Test cases:
- `parse([{"name": "Alice"}], ["name"])` → `[{"name": "Alice"}]`
- `parse({"name": "Alice"}, ["name"])` → `[{"name": "Alice"}]`
- `parse(json.dumps([{"name": "Alice"}]), ["name"])` → `[{"name": "Alice"}]`

**Backward compatibility (must continue to work):**
- `JsonParser(list_of_dicts, keys)` — existing behavior unchanged
- Existing tests (`test_get_data`, `test_get_args`, `test_dupe_keys`) must still pass
  </behavior>
  <implementation>
**In __init__.py:**

In `JsonParser.__init__`, BEFORE the existing truthiness checks, add two isinstance checks:

1. If `obj` is a `str`: call `json.loads(obj)` and catch `json.JSONDecodeError`, re-raising as `JsonParserException("Invalid JSON string: {e}")`. Assign the parsed result back to `obj` before any further validation.

2. If `obj` is a `dict` (after string parsing): wrap it in a list — `obj = [obj]`.

These two checks must come BEFORE `if not obj:` so that empty string and empty dict still hit the validation error paths.

**Module-level parse() function:**

After the JsonParser class definition, add:

```python
def parse(obj, keys):
    """One-liner convenience function. Equivalent to JsonParser(obj, keys).get_data()."""
    return JsonParser(obj, keys).get_data()
```

**Type hints:** Add Python 3.8-compatible type hints to `__init__` signature and `parse()`. Use `Union[str, dict, list]` from `typing` — NOT `str | dict | list` syntax (Python 3.10+ only).

**Import to add at top of __init__.py:** `import json` and `from typing import Union, List, Any`

**In tests/test_json_parser.py:**

- `test_parse_function_list()` — calls `parse()` with list-of-dicts
