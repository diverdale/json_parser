**Path tracking tests (FEAT-01) — path=True format decision:**
When path=True, each matched value is replaced by a dict: {"value": <original_value>, "path": "<dot.notation.path>"}. The path is built from the sequence of dict keys traversed to reach the match. Lists are transparent — they do not consume a path segment (list items are traversed without adding a segment). When the same key appears in multiple locations, the output for that key is a list of {"value": ..., "path": ...} dicts, one per match location.

Use the existing json_data fixture for these tests:

```python
def test_path_tracking_top_level():
    # first_name is at top level — path is just the key itself
    result = JsonParser(json_data, ['first_name']).get_data(path=True)
    assert result[0]['first_name'] == {"value": "John", "path": "first_name"}

def test_path_tracking_nested():
    # city appears inside address1 and address2
    result = JsonParser(json_data, ['city']).get_data(path=True)
    matches = result[0]['city']
    # Should be a list of two path-value dicts
    assert isinstance(matches, list)
    assert len(matches) == 2
    paths = {m['path'] for m in matches}
    assert paths == {"address1.city", "address2.city"}

def test_path_tracking_false_default():
    # path=False (default) must return bare values — no regression
    result = JsonParser(json_data, ['first_name']).get_data()
    assert result[0]['first_name'] == "John"
```

**Depth limiting tests (FEAT-02) — depth semantics:**
Depth 1 = immediate keys of the top-level dict. Descending into a nested dict increments depth by 1. Lists are transparent (traversing a list's items does not consume a depth level). max_depth=None = unlimited (existing behavior). max_depth=0 = only top-level keys, no recursion.

```python
def test_max_depth_none_default():
    # Default (max_depth=None) still finds nested keys
    result = JsonParser(json_data, ['city']).get_data()
    assert 'city' in result[0]

def test_max_depth_1_excludes_nested():
    # city lives inside address1/address2 (depth 2) — should NOT be found at max_depth=1
    result = JsonParser(json_data, ['city']).get_data(max_depth=1)
    assert 'city' not in result[0]

def test_max_depth_1_includes_top_level():
    # first_name is at depth 1 (top level) — should be found
    result = JsonParser(json_data, ['first_name']).get_data(max_depth=1)
    assert result[0]['first_name'] == "John"

def test_max_depth_2_includes_nested():
    # city is at depth 2 (inside address1) — should be found at max_depth=2
    result = JsonParser(json_data, ['city']).get_data(max_depth=2)
    assert 'city' in result[0]

def test_max_depth_0_returns_empty():
    # max_depth=0 means no keys at all — nothing at depth 0 (only at depth 1+)
    result = JsonParser(json_data, ['first_name']).get_data(max_depth=0)
    assert result[0] == {}
```

**Step 1 — Extract search_dict into a method:**
Move the existing nested `search_dict()` function out of `get_data()` and make it a private instance method `_search_dict(dct, keys_to_search, current_path="", depth=1, max_depth=None, path=False)`. This is the foundational change that allows both features to work cleanly.

**Step 3 — Implement depth limiting in _search_dict:**
- Add `current_depth: int` and `max_depth: Optional[int]` params to `_search_dict`.
- At the start of each recursive descent (before calling `_search_dict` on a nested dict or list item), check `if max_depth is not None and current_depth >= max_depth: return {}` — do not recurse further.
- Top-level call from `get_data()` passes `current_depth=1`. Each recursive call increments: `current_depth + 1`.
- Lists are transparent: when iterating list items to recurse, pass the SAME `current_depth` (not +1). Only descending into a dict increments depth.
- `max_depth=0` behavior: initial check `if max_depth is not None and max_depth == 0: return {}` at the top of `_search_dict` ensures nothing is returned.

**Step 4 — Implement path tracking in _search_dict:**
- Add `current_path: str` and `path: bool` params to `_search_dict`.
- When a key matches and `path=True`, store `{"value": value, "path": <full_path>}` instead of the raw value.
- Build `full_path` as: `f"{current_path}.{key}" if current_path else key`.
- When recursing into a nested dict, pass `current_path=full_path_of_current_key` (i.e. the key being descended into). Example: for key `address1` whose value is a dict, recurse with `current_path="address1"` so that `city` inside it gets path `"address1.city"`.
- When recursing into list items (transparent), pass the same `current_path` as the containing key. Example: items in a list under key `contacts` recurse with `current_path="contacts"`.
- Merging with `path=True`: same key found multiple times should produce a list of `{"value": ..., "path": ...}` dicts. The merge logic must handle: first match stores the dict, second match converts to list of dicts, subsequent matches append. When `path=False` (default), existing merge behavior is unchanged.

**Step 5 — Update get_data() call site:**
```python
def get_data(self, path: bool = False, max_depth: Optional[int] = None) -> List[Any]:
    result = []
    for item in self.json_obj:
        if isinstance(item, dict):
            result.append(self._search_dict(item, self.args, current_path="", current_depth=1, max_depth=max_depth, path=path))
    return result
```

**Step 6 — Update parse() to accept new params:**
```python
def parse(obj: Union[str, dict, list], keys: List[str], path: bool = False, max_depth: Optional[int] = None) -> List[Any]:
    """One-liner convenience function. Equivalent to JsonParser(obj, keys).get_data(path=path, max_depth=max_depth)."""
    return JsonParser(obj, keys).get_data(path=path, max_depth=max_depth)
```
